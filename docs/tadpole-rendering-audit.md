# Сравнение рендера Tadpole со штатным multiz TGMC

Проверен upstream `tgstation/TerraGov-Marine-Corps`, commit
`47c129f4103af6b77103da2ee7ccf7beeabcbcff` (2026-11-14).

## Что делает upstream

- [turf_transparency.dm](https://github.com/tgstation/TerraGov-Marine-Corps/blob/47c129f4103af6b77103da2ee7ccf7beeabcbcff/code/datums/elements/turf_transparency.dm):
  `z_pillar` подключает настоящий нижний turf через `vis_contents`, учитывает
  несколько источников видимости, соседний ряд тайлов и замену верхних турфов.
  Движение, вложенные визуальные объекты и анимации остаются нативными.
- [plane_master_group.dm](https://github.com/tgstation/TerraGov-Marine-Corps/blob/47c129f4103af6b77103da2ee7ccf7beeabcbcff/code/_onclick/hud/rendering/plane_master_group.dm):
  у каждого визуального z есть группа plane masters, смещение render targets,
  клиентские настройки дальности/масштаба multiz.
- [render_plate.dm](https://github.com/tgstation/TerraGov-Marine-Corps/blob/47c129f4103af6b77103da2ee7ccf7beeabcbcff/code/_onclick/hud/rendering/render_plate.dm)
  и [plane_master_subtypes.dm](https://github.com/tgstation/TerraGov-Marine-Corps/blob/47c129f4103af6b77103da2ee7ccf7beeabcbcff/code/_onclick/hud/rendering/plane_masters/plane_master_subtypes.dm):
  геометрия, статический/динамический свет, emissive, маски и bloom проходят
  через отдельные relays/plates. Видимость определяется также клиентом.

## Применённые исправления

| Область | Пробел в Tadpole | Исправление |
|---|---|---|
| Вложенные визуальные объекты | `atom.appearance` не содержит `vis_contents`; пропадали купола, кабели и другие присоединённые визуальные объекты | Нормализованное копирование дерева movable-vis-объектов, `VIS_HIDE`, `VIS_UNDERLAY`, наследование направления/слоя; кэш учитывает добавление, изменение и удаление дочерних объектов; поддержано также наследование icon/icon_state |
| Перекрытие при движении | Слой моба сразу соответствовал конечному тайлу, а сам спрайт ещё скользил | Глубина вычисляется по интерполированному положению существующего якоря |
| Край видимой области | Запас для движения камеры не включал отдельный соседний ряд для нависающих спрайтов | Добавлен один ряд по экранным границам и соответствующий запас при обратном преобразовании координат |
| Движущиеся предметы и транспорт | Снимки могли оставлять старые копии предметов и пропускать движения между опросами | Постоянные якоря для незафиксированных предметов, транспорта и снарядов; настоящие Move/forceMove, удаление и уход в инвентарь обрабатываются сигналами; занятые тайлы учитываются отдельно от корня |
| Изменения статичной геометрии | После снижения частоты обработки дверь могла ждать фонового опроса | Приоритетная очередь по сигналам иконки, направления, перемещения и удаления в том же общем лимите; уходящая копия удаляется сразу |
| Свет | Серверное семплирование текстур и обход теневых треугольников для каждого видимого тайла перегружали сервер | Расчёт удалён. Отдельные plane masters собирают геометрию и свет; готовые native static underlays и ambient appearances используются без пересчёта. Каждый hybrid-источник представлен одной маской со штатными преобразованием, blur, теневыми overlays и alpha-фильтром. Сложение и умножение света выполняет клиент |
| Видимость | Все ненулевые уровни invisibility исключались до попадания в клиент | Корневые визуальные копии сохраняют invisibility исходника; see_invisible остаётся решением клиента; служебный уровень 101 не ретранслируется |
| Смена z | Быстрый путь кэша сравнивал только x/y/heading | z включён в ключ; старые тайлы и якоря удаляются обычной очисткой |

Сохраняются прежние исправления: единое преобразование собранной поверхности,
нормализация planes без изменения настоящей карты, TOPDOWN-сортировка внутри
композита, постоянные якоря движущихся атомов, обработка сглаженных направлений, приватных
render targets и очистка управления/визуальных объектов при посадке.

Частота контроллера возвращена на стандартный `SSfastprocess` (0,2 секунды).
Отдельная `SSsuperfastprocess` удалена. Движения объектов ретранслируются
сигналами независимо от этого таймера.

## Существенные различия, которые остаются

Это не полный перенос штатного multiz. Tadpole находится на отдельном transit z,
а наземная точка произвольная и поворачивается. Прямой `vis_contents += turf`
сохраняет настоящие planes и ранее выводил наземные объекты поверх шаттла.
В текущей архитектуре используются нормализованные копии.

- Освещение использует отдельный проход plane masters: геометрия → свет
  (`BLEND_MULTIPLY`) → итоговая сцена ниже пола Tadpole. Тени не вычисляются
  повторно: копируются готовые overlays штатной маски с отдельным render target,
  исключающим влияние на свет настоящего шаттла. Статические маски сравниваются
  по immutable appearances, без выделения сигнатуры/цветовой матрицы на каждом кадре.
  Hybrid-маски обновляются один раз на источник, не на каждый освещённый тайл.
  Полный emissive/bloom pipeline и клиентские cutoffs пока не перенесены.
- Нативные произвольные `animate()`/`flick()` исходных объектов не копируются
  самим снимком appearance. Перемещение корней мобов, предметов и транспорта
  воспроизводится сигналами. Анимации произвольных свойств и подтайловая
  анимация снарядов не равнозначны всему клиентскому animation timeline.
- Вложенные movable-vis-объекты теперь включены, но это снимки: все специальные
  режимы наследования/анимации и отдельная смена DMI-направления каждого
  вложенного объекта не эквивалентны настоящему дереву vis_contents.
- Корневые копии передают invisibility клиенту без глобального раскрытия.
  Вложенные невидимые vis-объекты пока консервативно исключаются. Композит
  остаётся общим: FOV, night vision и multiz preferences не равнозначны
  отдельному набору штатных plane masters для каждого наблюдателя.
- Просмотр нескольких настоящих уровней через цепочку openspace/прозрачных
  полов и физика zFall не портировались. Полёт и выпадение из Tadpole используют
  его логические координаты; физическое перемещение корабля остаётся штатным.

## Проверки

Регрессии проверяют неизменность исходного appearance при присоединении vis-объекта,
инвалидацию кэша и `VIS_HIDE`, нормализацию дочерних planes, присоединение/удаление
визуальных объектов у моба, глубину в середине настоящего Move/glide и смену z
при неизменных x/y/heading. Сборка/тесты не заменяют проверку игровым клиентом.

Дополнительные регрессии проверяют настоящие Move/forceMove предметов и
транспорта, отсутствие статичных дублей, уход в инвентарь, invisibility,
приоритетную очередь без превышения бюджета и многотайловые границы.
Световой тест проверяет повторное использование native appearances, отдельный
проход света, одну маску на источник, сохранение её матрицы и удаление вышедших
из области источников. Серверных `GetPixel`, обхода shadow polygons и расчёта
угловой матрицы в полётном контроллере больше нет.

Это замена дорогостоящего освещения, а не полный перенос `turf_transparency`:
геометрия всё ещё использует описанные выше копии. Производительность и вид
нового прохода требуют отдельной проверки игровым клиентом.

## Исправление группировки светового прохода

Световые дети поверхности должны иметь `KEEP_APART | KEEP_TOGETHER`:
первый флаг выводит их из группы геометрии, второй сохраняет собственную
группу underlays/теневых overlays. Без `KEEP_APART` они закрашивали геометрию
внутри родительского `KEEP_TOGETHER`, несмотря на отдельный plane.
Регрессия проверяет это условие для статической и hybrid-маски.
